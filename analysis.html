SQL Relational Data Analysis

The cleaned student survey dataset (N = 405) was organized into two related relational tables: Students and Social Media Platforms. Using Structured Query Language (SQL), we perform relational modeling, subgroup filtering, cohort grouping, and aggregate evaluations to analyze behavioral distributions, assess distraction dynamics, and test our research hypotheses.

🗄️ Relational Database Schema: Two Related Tables

Our database architecture organizes the 405 survey records into two relational tables:

1. Students

Main entity table storing individual survey responses (405 student records):

  • student_id (Primary Key)
  • age
  • gender
  • screen_time_hours
  • study_time_hours
  • platform_id (Foreign Key)
  • academic_distraction_scale
  • gpa
  • usage_level

2. Social Media Platforms

Lookup reference table storing platform metadata and content types:

  • platform_id (Primary Key)
  • platform_name
  • category_type
  • primary_format

🔗 Table Relationship

Relationship: Students.platform_id → Social Media Platforms.platform_id

The tables are joined through platform_id. In the Students table, platform_id is a Foreign Key referencing platform_id in the Social Media Platforms table. This represents a One-to-Many (1:N) relationship: each platform can be associated with multiple student respondents, while each student reports one primary platform.

[Students Table] [Social Media Platforms Table] • student_id (PK) • platform_id (PK) • age ───► • platform_name • gender • category_type • screen_time_hours • primary_format • study_time_hours • platform_id (FK) ────────────────────────┘ • academic_distraction_scale • gpa • usage_level

💻 SQL Table Creation Statements (CREATE TABLE)

-- Table 1: Create Social Media Platforms Reference Table CREATE TABLE social_media_platforms ( platform_id INT PRIMARY KEY, platform_name VARCHAR(50) NOT NULL, category_type VARCHAR(50), primary_format VARCHAR(50) ); -- Table 2: Create Students Main Entity Table with Foreign Key CREATE TABLE students ( student_id INT PRIMARY KEY, age INT, gender VARCHAR(10), screen_time_hours DECIMAL(4,2), study_time_hours DECIMAL(4,2), platform_id INT, academic_distraction_scale INT, gpa DECIMAL(3,2), usage_level VARCHAR(15), FOREIGN KEY (platform_id) REFERENCES social_media_platforms(platform_id) );

Query 2: High Screen Time Filtering

WHERE Filtering
Purpose: Filter student records to isolate high-intensity social media users who spend more than 7 hours per day on networking platforms.
SELECT student_id, age, gender, screen_time_hours, gpa FROM students WHERE screen_time_hours > 7.0 LIMIT 5;
Explanation: The WHERE predicate filters the dataset to retain only rows where screen_time_hours exceeds 7.0, corresponding to the "High" usage bracket.

Query 3: Heavy Usage & High Distraction Identification

WHERE • Multiple Conditions (AND)
Purpose: Identify the count of students who simultaneously report heavy daily screen time (≥ 5 hours) and high self-reported academic distraction (≥ 4 on a 1–5 scale).
SELECT COUNT(*) AS high_screen_and_distraction_count FROM students WHERE screen_time_hours >= 5.0 AND academic_distraction_scale >= 4;
Explanation: Combines multiple boolean conditions using the logical AND operator to pinpoint students meeting both criteria.

Query 4: Top Screen Time Ranking

ORDER BY Sorting
Purpose: Sort participants in descending order by daily screen time to inspect top screen time consumers, using study time as a secondary ascending sort.
SELECT student_id, screen_time_hours, study_time_hours, gpa, usage_level FROM students ORDER BY screen_time_hours DESC, study_time_hours ASC LIMIT 5;
Explanation: The ORDER BY clause sorts rows primarily by screen_time_hours DESC (highest first) and secondarily by study_time_hours ASC.

Query 5: Sample Summary Aggregation

COUNT / AVG Aggregation
Purpose: Calculate overall descriptive statistics across the entire sample of 405 students, including respondent count, average hours, and range bounds.
SELECT COUNT(*) AS total_students, ROUND(AVG(screen_time_hours), 2) AS avg_screen_time, ROUND(AVG(study_time_hours), 2) AS avg_study_time, MIN(screen_time_hours) AS min_screen_time, MAX(screen_time_hours) AS max_screen_time FROM students;
Explanation: Employs aggregate functions (COUNT, AVG, MIN, MAX) combined with ROUND() to summarize the sample in a single row.
Query Output:

Query 6: Study Time by Usage Level (Source for Graph 2)

GROUP BY Comparison
Purpose: Group students by daily usage tier (Low, Moderate, High) to count participants per tier and compare average daily study hours.
SELECT usage_level, COUNT(*) AS student_count, ROUND(AVG(study_time_hours), 2) AS avg_study_hours FROM students GROUP BY usage_level ORDER BY student_count DESC;
Explanation: The GROUP BY clause partitions rows into the three discrete usage categories, aggregating student counts and average study hours for each group.

Query 7: Major Age Cohort Screen Time Analysis

HAVING Clause
Purpose: Group participants by age and apply the HAVING clause to filter out smaller age brackets, displaying only age cohorts with at least 15 respondents.
SELECT age, COUNT(*) AS student_count, ROUND(AVG(screen_time_hours), 2) AS avg_screen_time FROM students GROUP BY age HAVING COUNT(*) >= 15 ORDER BY student_count DESC;
Explanation: While WHERE filters individual rows before grouping, HAVING filters aggregated groups after the GROUP BY operation (here, retaining only groups where COUNT(*) ≥ 15).

Query 8: Multi-Table Platform Usage Aggregation (Source for Graph 1)

JOIN Between Two Tables
Purpose: Perform an INNER JOIN linking the Students table with the Social Media Platforms lookup table to calculate total student counts and average screen time by platform name and category.
SELECT p.platform_name, p.category_type, COUNT(s.student_id) AS student_count, ROUND(AVG(s.screen_time_hours), 2) AS avg_screen_hours FROM students s JOIN social_media_platforms p ON s.platform_id = p.platform_id GROUP BY p.platform_id, p.platform_name, p.category_type ORDER BY student_count DESC;
Explanation: Combines rows from students and social_media_platforms where s.platform_id = p.platform_id, allowing platform descriptive attributes to be combined with individual student behaviors.

🔬 Research Connection

Relational SQL operations provide an efficient, transparent, and reproducible methodology to answer our core research questions:

  • SQL Filtering (WHERE & Multiple Conditions): Allows us to isolate high-risk behavioral cohorts. In Query 3, combining multiple conditions identified that 55 students (13.6%) concurrently experience ≥ 5.0 hours of daily screen time and severe academic distraction (≥ 4 on a 1–5 scale), evidencing active study interference (supporting Hypothesis 2).
  • SQL Grouping & Aggregation (GROUP BY, COUNT, AVG): Enables empirical comparisons across usage tiers. In Query 6, aggregating average study hours reveals a continuous drop from 3.84 hours for Low users down to 3.28 hours for Moderate users and 2.72 hours for High users—demonstrating a 1.12-hour daily study deficit and validating the time-displacement principle (supporting Hypothesis 1).
  • Relational Table JOINs: Links individual student behavioral metrics with platform metadata (Query 8), demonstrating how screen time and engagement patterns vary systematically across specific social networking environments (Facebook 137, Instagram 125, YouTube 121, Other 18, TikTok 4).
